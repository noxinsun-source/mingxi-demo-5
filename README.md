# 明晰 Demo 5.0

“明晰”产品 Demo 的干净、可复现源码仓库，面向产品评审、交互演示和前端方案交接。

> **先说清楚：这是产品 Demo / 评审交付仓库，不是已经可投入生产的完整“明晰”系统。**
>
> 仓库可以启动完整网页，包含高保真界面、60 篇演示银标笔记、领域旭日、梳逻辑线、知识扩展、手机捕获等交互，也保留了部分 API 路由、模型适配器和本地降级逻辑。但“仓库里存在 API 或 Agent 代码”不等于每一项产品能力都已经接入真实数据源、真实联网服务并完成持久化。

## 这个仓库是什么

- 是：明晰 Demo 5.0 的产品演示、评审和交接仓库。
- 是：一套可以本地启动、可以在线展示的 Next.js / React 全栈 Demo 源码。
- 是：用于说明信息架构、视觉规范、页面状态、关键交互和目标产品闭环的参考实现。
- 不是：可直接服务真实用户的生产系统。
- 不是：完整的多用户知识库后端、生产级搜索服务或持久化知识图谱平台。
- 不是：Knowledge Completion、Knowledge Network、Notegraph Studio 等独立项目的合集。

## 真实能力与演示能力边界

| 功能 | 本仓库当前性质 | 说明 |
| --- | --- | --- |
| 笔记库与领域旭日 | 基于演示数据真实渲染 | 使用仓库内 60 篇银标笔记生成领域结构，适合评审信息架构和可视化交互；不等于已经接入个人真实知识库。 |
| 手机捕获、用途确认、梳逻辑线 | 可运行 Demo + 局部真实链路 | 含 API、规则、Agent/LLM 适配与本地降级；是否调用真实模型取决于本机环境变量，默认演示不携带任何密钥。 |
| 第四页“知识扩展 / 知识补全” | **高保真前端交互 Demo** | 当前使用内置起点笔记、预制多跳知识节点和演示搜索结果；筛选、粒度切换、3–6 跳延伸、阅读和保存均用于展示产品交互。 |
| “外查核实” | **前端核实流程 Demo** | 展示定义问题、审阅证据、形成结论和写回的完整流程；当前资料是录制/演示数据，不应被当作实时搜索结论。 |

尤其需要强调：本仓库中的“知识扩展”**没有实现**下面这条生产级核心链路：

```text
任意输入一篇真实笔记
→ 后端理解内容并生成多粒度、多跳知识图谱
→ 实时联网检索并读取来源
→ 证据审阅
→ 持久化 runId / 图谱 / 搜索记录
→ 跨会话恢复与继续扩展
```

当前第四页的搜索结果由前端演示数据生成，保存操作只改变本次 Demo 的界面状态，不会写入独立知识补全系统。真正面向上述链路的独立实现位于 [noxinsun-source/knowledge-completion](https://github.com/noxinsun-source/knowledge-completion)，它与本 Demo 仓库分开维护。

## 为什么仓库里仍然有 API、数据库迁移和 Agent 代码

因为这是“可运行的全栈产品 Demo”，而不是一张静态效果图。部分页面需要 API 路由、本地数据处理、可选模型调用和降级路径来完整演示产品流程；这些代码也便于后续继续接真实服务。但当前仓库没有生产所需的账户权限、租户隔离、稳定联网检索、任务队列、完整持久化、监控审计和安全治理，不能据此宣称整套产品已经后端打通。

## 为什么 GitHub Pages 不是完整应用本体

本项目包含 `/api/mingxi/*` 后端路由，不是单个静态 HTML。GitHub Pages 托管根目录的 `index.html` 作为公开入口；完整交互运行在全栈部署地址。仓库中仍保留全部可运行源码。

## 本地运行

需要 Node.js 22.13 或更高版本：

```bash
npm ci
npm run dev
```

浏览器打开 <http://localhost:4317/demo>。

## 仓库范围

仅保留明晰 Demo 所需的应用路由、组件、业务逻辑、演示数据、媒体素材、构建配置和数据库迁移。仓库不包含 `.env`、API 密钥、`node_modules`、构建缓存、Git 历史、个人会话、个人笔记或其他独立实验项目。

更多交付说明见 [README-评审交付.md](./README-评审交付.md)。
